什么是 Gov4Git（GitRules）？

很多人一起写程式码或文件时，用来记录并执行「谁是成员、谁有多少发言权、要采用哪些稿件」的开源工具。它被用在《多元宇宙》的写作中，2024 年改名为 GitRules。

几个人一起写文件，商量一下就能决定。可是参与者一旦有几百、几千人，「先处理谁的提案」「怎么认可谁的贡献」，就很难靠现场气氛决定。Gov4Git 就是一个试图把这种「很多人一起做东西时的决定方式」，做成软件机制的工具。

一句话说明

Gov4Git 是在 git（记录、共享档案变更历史的机制，GitHub 是代表性的服务）之上，记录并执行以下事项的开源工具（以任何人都能使用、改良的形式公开的软件）[1][2]：

  • 谁是社群的成员
  • 谁持有多少「积分」（可用于发言和投票的点数）
  • 要优先处理哪些议题、采用哪些稿件

由参与者大家各自保存纪录副本这一点，和区块链（由许多人共享交易纪录以防窜改的机制）相似。但说明中指出，不同之处在于它不是用金钱报酬驱动人，而是依靠因为想参与、所以保存纪录这种开源的动机[2]。2024 年改名为 GitRules[3]。

举例来说

《多元宇宙》的写作（2024 年）。 这本书是由许多贡献者写成的，支撑其营运规则多元管理协定（PMP）运作的就是 Gov4Git。作者、经济学者卫谷伦（E. Glen Weyl）在 2024 年 3 月 2 日宣布，Gov4Git 的公开版已经启动，登记的人就能得到积分[4]。想参加的人，会在 GitHub 上自动产生「我想加入这个社群」的请求（issue），经管理者核准后加入[5]。

英文版 5-0 章写道，优先排序、核准与贡献认定的纪录，都透过「以开源参与而非金钱诱因为基础」的协定 GitRules，记录在分散式帐本上[6]（目前的繁体中文版 5-0 章没有这一句）。

日本参与者的试用（2024 年 3 月）。 日文翻译社群（plurality-japanese）里，有参与者自己建立试验用的环境（沙盒），试着当管理者的纪录：需要 GitHub 的「组织」帐号、在权限设定上卡关、投票结果要几个小时才会反映。这位参与者留下的感想是：用在小小的决定上还不太方便，但几个小时就能建立类似游戏货币的东西，让人觉得有可能性[7]。

运作方式

开端

2022 年 9 月 15 日，Protocol Labs 宣布成为本书项目的技术伙伴，要打造「Governance for Git」。构想是把治理（集体的决定方式）看作 git 贡献者共享的程序，并把它的历史以无法窜改的形式嵌入 git 的历史中[8]。

依白皮书（说明设计的文件），本书项目预期贡献者会有数百到数千人。这超过了一般认为人能维持面对面关系的上限「邓巴数」，所以需要不是临时凑合的机制[9]。

为什么需要

2023 年 3 月微软研究院的文章（卫谷伦等人）指出，开源世界缺乏方便又安全的治理机制，因此许多社群没有诞生，也长不大。文章也提到，随着生成式 AI 普及，伪装成合作者的恶意参与者可能增加[10]。

最初试作的核心有两个：用平方投票（越把很多票集中在一处就越贵的投票法）决定稿件的优先顺序；以及像投票用积分这样只在社群内通用的「货币」[10]。文章也写道，要让那些创始的单一领导者已经负荷不了的社群，能够自己延续下去[10]。

和区块链的不同

依白皮书，Gov4Git 的纪录是单一社群专用的。要求互相冲突时，由该社群的治理规则裁决。所以不需要像公开区块链那样，用耗电的计算竞赛决定胜者；在小型电脑（Raspberry Pi）或 GitHub 的免费自动执行环境上也能运作[9]。

白皮书也举出另一个理由：公开区块链的位置为人所知，可能被威权国家锁定封锁[9]。开发者 Petar Maymounkov 在 2023 年的 Podcast 中表示，大意是：公开区块链是为了在全球高速处理许多应用而设计的，而单一社群内由人来讨论决定的治理，用不到其中大部分功能，所以选择了不同的设计[11]。

用法与扩散

依说明书（README），平常必要的基础设施只有 git 的存放处，不是技术人员的人也能从桌面应用程式使用[1]。本书项目的说明写道，这套机制不是 PMP 专用，而是几乎可以承载任何决定方式的底座；本书在上面用的是 PMP[2]。

开发团队自己也用 Gov4Git 管理开发计划[12]。艺术文化平台 Cube Commons、地球科学软件 EarthSciML 也采用了它[13]。

改了名字

Gov4Git 在 2024 年 3 月宣布改名为 GitRules。依日文社群的纪录，到 4 月 10 日，书的正文中的「Gov4Git」已全部换成「GitRules」。西尾泰和写道，连「旧 Gov4Git」都没写，可能会有人不知道两者的关系[3][5]。

争议与批评

  • 参与门槛高。 日文的安装步骤笔记写道，对不熟悉 git 的人来说，要轻松试用门槛很高。笔记也记下一个疑问：这是贡献越多、发言权越大的机制，对不是特别想发言的人来说，参与的意义是不是很薄弱？[14]
  • 无法参与的例子。 2025 年 3 月，一位用户报告，因为 GitHub 的个人帐号与组织名称对不上，无法从应用程式参与。卫谷伦道歉后，回复的大意是：自己不知道解决办法，开发者也许有想法[15]。
  • 是区块链，还是不是？ 介绍文写的是「类似区块链」，白皮书称之为「治理的区块链」。不过它和公开区块链不同，不使用金钱诱因，也不使用计算竞赛[2][9]。要注意别只看名称就以为是同一种东西。

在《Plurality》中的位置

英文版 5-0 章〈协作技术与民主〉在说明本书本身的做法时提到 GitRules[6]。本书的营运文件说明，积分帐本由全体成员的 git 各自保存副本，不一致时以治理程序解决[16]。

Gov4Git 是执行本书营运规则多元管理协定的底座，也是记录在其中发放的 ⿻ 积分的帐本。卫谷伦在 2023 年 12 月的视频讯息中表示，大意是：参与者把自己维护资料库当作参与的一部分，这一点是和区块链的不同[17]。很多人一起写书的尝试，本身也是创意协作的实例。
