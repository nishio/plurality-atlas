Petar Maymounkov 是谁？

负责让许多人一起撰写、营运《Plurality》的机制 Gov4Git（后来的 GitRules）与多元管理协定之技术面的技术者。当时是 Protocol Labs 的研究者。

《Plurality》不是只由两位主要作者写成的书。几十个人参与其中，谁写什么、接受哪些修改，都是大家一边决定一边做出来的。打造这种决定方式之「工具」的技术者之一，就是 Petar Maymounkov。

一句话说明

Petar Maymounkov 是打造 Gov4Git 这个工具的技术者之一，负责它的技术面[1][2]。

Gov4Git 是在 git 之上，连「谁决定什么」都包含在内，营运任何人都能参与之协作（开源）的工具。git 是记录文章或程式变更历史的工具[1][2]。《Plurality》除了两位主要作者，还由几十个人一起写成。工作的优先顺序、稿件的采用与否、贡献的纪录，都用了这个机制[3][4][5]。→ Gov4Git（GitRules）

与《Plurality》的关系

书的「技术」贡献者。 书用「⿻ 積分」的纪录表示贡献者。Maymounkov 列在「技术」（Technical）类别的第 2 位[6]。

参与的经过。 在 2023 年 Microsoft Research 的 podcast 中，Maymounkov 说自己在 Protocol Labs 工作了约三年半。最初几年作为工程师，身在分散式开发的现场，看到了行得通的事与需要改善的事；由此开始处理治理（governance）的问题，研究之中遇到了卫谷伦（E. Glen Weyl）的工作。Maymounkov 也说，卫谷伦正要开始的「plurality book」作为具体的课题，让这些努力有了形状。节目中的头衔是 Protocol Labs 的 Research Scientist（研究者）[1]。

Protocol Labs 与本书项目的合作。 2022 年 9 月 15 日，Protocol Labs 宣布与卫谷伦、唐凤（Audrey Tang）合作，作为本书项目的技术伙伴打造「Governance for Git」[7]。

介绍 Gov4Git 的文章。 2023 年 3 月 19 日，Maymounkov 与卫谷伦、Kasia Sitkiewicz（GitHub）合写了 Microsoft Research 的文章 "Gov4git: A Decentralized Platform for Community Governance"。文章说明，Microsoft Research 与 Protocol Labs 正在一起打造一种在 git 上运作的机制：具备像区块链那样的透明与分散，但不依赖成本高昂的手段[2]。

PMP 的说明文。 GitHub 上的 issue #333 "Gov4Git and the Plural Management Protocol overview"（2024 年 2 月 26 日）的发文者，就是 Maymounkov（petar）[4]。英文版 5-7 章以「本书制作所用的 Plural Management Protocol」连结到这个 issue[5]。繁体中文版 5-7 章写道：「我们在编写本书时使用的『多元管理协定』，可追踪不同参与者所作贡献的类型和程度」[12]。→ 多元管理协定

论文〈Plural Management〉。 这是 Tobin South、Leon Erichsen、Shrey Jain、Maymounkov、Scott Moore 与卫谷伦的共同著作（2024 年 1 月）。英文版 5-0 章在注脚中引用了它[8][9]。

主要想法

治理就是「可信计算」。 Maymounkov 在 podcast 中说明，从电脑科学来看，治理和 trusted computation（可信计算）是同一个意思：治理的规则以公开的程式存在，共同体的成员能确认它是否照约定执行[1]。

现在的区块链，实作还追不上野心。 在同一个节目中，Maymounkov 说，现在的区块链技术很有前景，但目前野心扩得太大，还没能完全兑现（总有一天会兑现）。大意是：在 git 上，可以更轻松地得到类似的保证[1]。

多元管理协定。 根据 issue #333，机制如下[4]。

  1. 投稿者会得到无法转让给他人的贡献凭证「Plural credits」，不能出售
  2. 用 credits 决定 GitHub 上 issue（该做的工作）的优先顺序，方式是平方募资的一种
  3. 解决优先顺序高之 issue 的人，会依优先程度得到 credits
  4. 是否接受 PR（投稿），用票数越多、成本按平方增加的平方投票决定

把帐本复制到 git 上保存。 issue #333 说明，Gov4Git 的帐本不是放在区块链上，而是复制到全体成员的 git 仓库。和一般的区块链不同，这里不放金钱上的回报；成员复制帐本的理由，和复制 git 程式码的理由相同，也就是为了参与共同体[4]。

根据日文翻译社群的纪录，到 2024 年 4 月，正文中的「Gov4Git」一词已经被换成「GitRules」[10]。

争议与批评

  • 参与的困难。 2025 年 3 月，本书的 GitHub 上出现了 issue #1071，回报因为 GitHub 用户名称与组织名称不同，无法从 Gov4Git 的应用程式参与[11]。卫谷伦回复的大意是：很抱歉，不知道该怎么办，@petar（Maymounkov）也许有想法[11]。这是一个以任何人都能参与为目标的机制，在实际的易用性上受挫的例子。
