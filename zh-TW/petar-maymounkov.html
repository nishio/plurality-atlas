Petar Maymounkov 是誰？

負責讓許多人一起撰寫、營運《Plurality》的機制 Gov4Git（後來的 GitRules）與多元管理協定之技術面的技術者。當時是 Protocol Labs 的研究者。

《Plurality》不是只由兩位主要作者寫成的書。幾十個人參與其中，誰寫什麼、接受哪些修改，都是大家一邊決定一邊做出來的。打造這種決定方式之「工具」的技術者之一，就是 Petar Maymounkov。

一句話說明

Petar Maymounkov 是打造 Gov4Git 這個工具的技術者之一，負責它的技術面[1][2]。

Gov4Git 是在 git 之上，連「誰決定什麼」都包含在內，營運任何人都能參與之協作（開源）的工具。git 是記錄文章或程式變更歷史的工具[1][2]。《Plurality》除了兩位主要作者，還由幾十個人一起寫成。工作的優先順序、稿件的採用與否、貢獻的紀錄，都用了這個機制[3][4][5]。→ Gov4Git（GitRules）

與《Plurality》的關係

書的「技術」貢獻者。 書用「⿻ 積分」的紀錄表示貢獻者。Maymounkov 列在「技術」（Technical）類別的第 2 位[6]。

參與的經過。 在 2023 年 Microsoft Research 的 podcast 中，Maymounkov 說自己在 Protocol Labs 工作了約三年半。最初幾年作為工程師，身在分散式開發的現場，看到了行得通的事與需要改善的事；由此開始處理治理（governance）的問題，研究之中遇到了衛谷倫（E. Glen Weyl）的工作。Maymounkov 也說，衛谷倫正要開始的「plurality book」作為具體的課題，讓這些努力有了形狀。節目中的頭銜是 Protocol Labs 的 Research Scientist（研究者）[1]。

Protocol Labs 與本書專案的合作。 2022 年 9 月 15 日，Protocol Labs 宣布與衛谷倫、唐鳳（Audrey Tang）合作，作為本書專案的技術夥伴打造「Governance for Git」[7]。

介紹 Gov4Git 的文章。 2023 年 3 月 19 日，Maymounkov 與衛谷倫、Kasia Sitkiewicz（GitHub）合寫了 Microsoft Research 的文章 "Gov4git: A Decentralized Platform for Community Governance"。文章說明，Microsoft Research 與 Protocol Labs 正在一起打造一種在 git 上運作的機制：具備像區塊鏈那樣的透明與分散，但不依賴成本高昂的手段[2]。

PMP 的說明文。 GitHub 上的 issue #333 "Gov4Git and the Plural Management Protocol overview"（2024 年 2 月 26 日）的發文者，就是 Maymounkov（petar）[4]。英文版 5-7 章以「本書製作所用的 Plural Management Protocol」連結到這個 issue[5]。繁體中文版 5-7 章寫道：「我們在編寫本書時使用的『多元管理協定』，可追蹤不同參與者所作貢獻的類型和程度」[12]。→ 多元管理協定

論文〈Plural Management〉。 這是 Tobin South、Leon Erichsen、Shrey Jain、Maymounkov、Scott Moore 與衛谷倫的共同著作（2024 年 1 月）。英文版 5-0 章在註腳中引用了它[8][9]。

主要想法

治理就是「可信計算」。 Maymounkov 在 podcast 中說明，從電腦科學來看，治理和 trusted computation（可信計算）是同一個意思：治理的規則以公開的程式存在，共同體的成員能確認它是否照約定執行[1]。

現在的區塊鏈，實作還追不上野心。 在同一個節目中，Maymounkov 說，現在的區塊鏈技術很有前景，但目前野心擴得太大，還沒能完全兌現（總有一天會兌現）。大意是：在 git 上，可以更輕鬆地得到類似的保證[1]。

多元管理協定。 根據 issue #333，機制如下[4]。

  1. 投稿者會得到無法轉讓給他人的貢獻憑證「Plural credits」，不能出售
  2. 用 credits 決定 GitHub 上 issue（該做的工作）的優先順序，方式是平方募資的一種
  3. 解決優先順序高之 issue 的人，會依優先程度得到 credits
  4. 是否接受 PR（投稿），用票數越多、成本按平方增加的平方投票決定

把帳本複製到 git 上保存。 issue #333 說明，Gov4Git 的帳本不是放在區塊鏈上，而是複製到全體成員的 git 儲存庫。和一般的區塊鏈不同，這裡不放金錢上的回報；成員複製帳本的理由，和複製 git 程式碼的理由相同，也就是為了參與共同體[4]。

根據日文翻譯社群的紀錄，到 2024 年 4 月，正文中的「Gov4Git」一詞已經被換成「GitRules」[10]。

爭議與批評

  • 參與的困難。 2025 年 3 月，本書的 GitHub 上出現了 issue #1071，回報因為 GitHub 使用者名稱與組織名稱不同，無法從 Gov4Git 的應用程式參與[11]。衛谷倫回覆的大意是：很抱歉，不知道該怎麼辦，@petar（Maymounkov）也許有想法[11]。這是一個以任何人都能參與為目標的機制，在實際的易用性上受挫的例子。
