什麼是 Gov4Git（GitRules）？

很多人一起寫程式碼或文件時，用來記錄並執行「誰是成員、誰有多少發言權、要採用哪些稿件」的開源工具。它被用在《多元宇宙》的寫作中，2024 年改名為 GitRules。

幾個人一起寫文件，商量一下就能決定。可是參與者一旦有幾百、幾千人，「先處理誰的提案」「怎麼認可誰的貢獻」，就很難靠現場氣氛決定。Gov4Git 就是一個試圖把這種「很多人一起做東西時的決定方式」，做成軟體機制的工具。

一句話說明

Gov4Git 是在 git（記錄、共享檔案變更歷史的機制，GitHub 是代表性的服務）之上，記錄並執行以下事項的開源工具（以任何人都能使用、改良的形式公開的軟體）[1][2]：

  • 誰是社群的成員
  • 誰持有多少「積分」（可用於發言和投票的點數）
  • 要優先處理哪些議題、採用哪些稿件

由參與者大家各自保存紀錄副本這一點，和區塊鏈（由許多人共享交易紀錄以防竄改的機制）相似。但說明中指出，不同之處在於它不是用金錢報酬驅動人，而是依靠因為想參與、所以保存紀錄這種開源的動機[2]。2024 年改名為 GitRules[3]。

舉例來說

《多元宇宙》的寫作（2024 年）。 這本書是由許多貢獻者寫成的，支撐其營運規則多元管理協定（PMP）運作的就是 Gov4Git。作者、經濟學者衛谷倫（E. Glen Weyl）在 2024 年 3 月 2 日宣布，Gov4Git 的公開版已經啟動，登記的人就能得到積分[4]。想參加的人，會在 GitHub 上自動產生「我想加入這個社群」的請求（issue），經管理者核准後加入[5]。

英文版 5-0 章寫道，優先排序、核准與貢獻認定的紀錄，都透過「以開源參與而非金錢誘因為基礎」的協定 GitRules，記錄在分散式帳本上[6]（目前的繁體中文版 5-0 章沒有這一句）。

日本參與者的試用（2024 年 3 月）。 日文翻譯社群（plurality-japanese）裡，有參與者自己建立試驗用的環境（沙盒），試著當管理者的紀錄：需要 GitHub 的「組織」帳號、在權限設定上卡關、投票結果要幾個小時才會反映。這位參與者留下的感想是：用在小小的決定上還不太方便，但幾個小時就能建立類似遊戲貨幣的東西，讓人覺得有可能性[7]。

運作方式

開端

2022 年 9 月 15 日，Protocol Labs 宣布成為本書專案的技術夥伴，要打造「Governance for Git」。構想是把治理（集體的決定方式）看作 git 貢獻者共享的程序，並把它的歷史以無法竄改的形式嵌入 git 的歷史中[8]。

依白皮書（說明設計的文件），本書專案預期貢獻者會有數百到數千人。這超過了一般認為人能維持面對面關係的上限「鄧巴數」，所以需要不是臨時湊合的機制[9]。

為什麼需要

2023 年 3 月微軟研究院的文章（衛谷倫等人）指出，開源世界缺乏方便又安全的治理機制，因此許多社群沒有誕生，也長不大。文章也提到，隨著生成式 AI 普及，偽裝成合作者的惡意參與者可能增加[10]。

最初試作的核心有兩個：用平方投票（越把很多票集中在一處就越貴的投票法）決定稿件的優先順序；以及像投票用積分這樣只在社群內通用的「貨幣」[10]。文章也寫道，要讓那些創始的單一領導者已經負荷不了的社群，能夠自己延續下去[10]。

和區塊鏈的不同

依白皮書，Gov4Git 的紀錄是單一社群專用的。要求互相衝突時，由該社群的治理規則裁決。所以不需要像公開區塊鏈那樣，用耗電的計算競賽決定勝者；在小型電腦（Raspberry Pi）或 GitHub 的免費自動執行環境上也能運作[9]。

白皮書也舉出另一個理由：公開區塊鏈的位置為人所知，可能被威權國家鎖定封鎖[9]。開發者 Petar Maymounkov 在 2023 年的 Podcast 中表示，大意是：公開區塊鏈是為了在全球高速處理許多應用而設計的，而單一社群內由人來討論決定的治理，用不到其中大部分功能，所以選擇了不同的設計[11]。

用法與擴散

依說明書（README），平常必要的基礎設施只有 git 的存放處，不是技術人員的人也能從桌面應用程式使用[1]。本書專案的說明寫道，這套機制不是 PMP 專用，而是幾乎可以承載任何決定方式的底座；本書在上面用的是 PMP[2]。

開發團隊自己也用 Gov4Git 管理開發計畫[12]。藝術文化平台 Cube Commons、地球科學軟體 EarthSciML 也採用了它[13]。

改了名字

Gov4Git 在 2024 年 3 月宣布改名為 GitRules。依日文社群的紀錄，到 4 月 10 日，書的正文中的「Gov4Git」已全部換成「GitRules」。西尾泰和寫道，連「舊 Gov4Git」都沒寫，可能會有人不知道兩者的關係[3][5]。

爭議與批評

  • 參與門檻高。 日文的安裝步驟筆記寫道，對不熟悉 git 的人來說，要輕鬆試用門檻很高。筆記也記下一個疑問：這是貢獻越多、發言權越大的機制，對不是特別想發言的人來說，參與的意義是不是很薄弱？[14]
  • 無法參與的例子。 2025 年 3 月，一位使用者報告，因為 GitHub 的個人帳號與組織名稱對不上，無法從應用程式參與。衛谷倫道歉後，回覆的大意是：自己不知道解決辦法，開發者也許有想法[15]。
  • 是區塊鏈，還是不是？ 介紹文寫的是「類似區塊鏈」，白皮書稱之為「治理的區塊鏈」。不過它和公開區塊鏈不同，不使用金錢誘因，也不使用計算競賽[2][9]。要注意別只看名稱就以為是同一種東西。

在《Plurality》中的位置

英文版 5-0 章〈協作技術與民主〉在說明本書本身的做法時提到 GitRules[6]。本書的營運文件說明，積分帳本由全體成員的 git 各自保存副本，不一致時以治理程序解決[16]。

Gov4Git 是執行本書營運規則多元管理協定的底座，也是記錄在其中發放的 ⿻ 積分的帳本。衛谷倫在 2023 年 12 月的影片訊息中表示，大意是：參與者把自己維護資料庫當作參與的一部分，這一點是和區塊鏈的不同[17]。很多人一起寫書的嘗試，本身也是創意協作的實例。
