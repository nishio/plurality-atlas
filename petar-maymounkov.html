ペタル・マイムンコフってどんな人？

書籍『Plurality』を大勢で書き、運営するための仕組み Gov4Git（のちの GitRules）と Plural Management Protocol の技術面を担った技術者です。当時は Protocol Labs の研究者でした。

書籍『Plurality』は、二人の主な著者だけで書かれた本ではありません。何十人もの人が加わり、誰が何を書き、どの修正を受け入れるかを、みんなで決めながら作られました。その決め方の「道具」を作った技術者の一人が、この人です。

ひとことで言うと

ペタル・マイムンコフ（Petar Maymounkov）は、Gov4Git という道具を作った技術者の一人で、その技術面を担当しました[1][2]。

Gov4Git は、誰でも参加できる共同作業（オープンソース）を、「誰が何を決めるか」まで含めて git の上で運営するための道具です。git は、文章やプログラムの変更の履歴を記録する道具です[1][2]。書籍『Plurality』は、主な著者二人のほか何十人もの人の手で書かれました。その作業の優先順位づけや、寄稿の採否、貢献の記録に、この仕組みが使われました[3][4][5]。→ Gov4Git（GitRules）

Plurality とのかかわり

本の「技術」の貢献者。 本は、貢献した人を「⿻ クレジット」という記録で表しています。マイムンコフは「Technical（技術）」の区分の 2 番目に載っています[6]。

かかわった経緯。 2023 年の Microsoft Research のポッドキャストで、マイムンコフは、Protocol Labs に約 3 年半勤めてきたと話しました。最初の数年はエンジニアとして分散型の開発の現場にいて、うまくいくことも改善が要ることも見てきた。そこから統治（ガバナンス）の問題に取り組むようになり、調べるうちに グレン・ワイル の仕事に出会った、といいます。ワイルが始めようとしていた「plurality book」が、具体的な課題として取り組みに形を与えた、とも述べています。番組での肩書きは Protocol Labs の Research Scientist（研究者）です[1]。

Protocol Labs と本のプロジェクトの提携。 2022 年 9 月 15 日、Protocol Labs は、ワイルと オードリー・タン と組んで、本のプロジェクトの技術パートナーとして「Governance for Git」を作ると発表しました[7]。

Gov4Git の紹介記事。 2023 年 3 月 19 日、マイムンコフはワイル、Kasia Sitkiewicz（GitHub）と、Microsoft Research の記事「Gov4git: A Decentralized Platform for Community Governance」を書きました。Microsoft Research と Protocol Labs が一緒に、ブロックチェーンのような透明さと分散を持ちながら、費用の大きい手段に頼らない、git の上で動く仕組みを作っている、と説明しています[2]。

PMP の説明文。 GitHub の issue #333「Gov4Git and the Plural Management Protocol overview」（2024 年 2 月 26 日）を投稿したのが、マイムンコフ（petar）です[4]。本の 5-7 章は、「この本を作るのに使った Plural Management Protocol」として、この issue にリンクしています[5]。→ Plural Management Protocol

論文「Plural Management」。 Tobin South、Leon Erichsen、Shrey Jain、マイムンコフ、Scott Moore、ワイルの共著です（2024 年 1 月）。本の 5-0 章が脚注で引いています[8][9]。

主な考え

統治は「信頼できる計算」。 ポッドキャストでマイムンコフは、計算機科学から見ると、統治は trusted computation（信頼できる計算）と同じ意味だ、と説明しました。統治のルールが公開されたプログラムとしてあり、それが約束どおりに実行されていることを、共同体のメンバーが確かめられる、ということです[1]。

今のブロックチェーンは、野心に実装が追いついていない。 同じ番組で、今のブロックチェーンの技術は有望だが、いまのところ野心を広げすぎて、届け切れていない（いずれは届けるだろう）、と述べました。git の上なら、もっと手軽に同じような保証が得られる、という趣旨です[1]。

Plural Management Protocol。 issue #333 によれば、しくみは次のとおりです[4]。

  1. 寄稿した人は、他人に渡せない貢献のしるし「Plural credits」を受け取る。売ることはできない
  2. credits を使って、GitHub の issue（やるべき作業）の優先度を決める。やり方は クアドラティック・ファンディング の一種
  3. 優先度の高い issue を解決した人には、その優先度に応じた credits が払われる
  4. PR（寄稿）を受け入れるかどうかは、票を増やすほど費用が 2 乗で増える クアドラティック投票 で決める

台帳を git に写して持つ。 issue #333 は、Gov4Git の台帳は、ブロックチェーンではなくメンバー全員の git リポジトリに写されると説明しています。ふつうのブロックチェーンと違って、お金の見返りは入れません。メンバーは、git のコードを写すのと同じ理由、つまり共同体に参加するために台帳を写す、という考えです[4]。

日本語の翻訳コミュニティの記録によれば、2024 年 4 月には、本文の「Gov4Git」という語が「GitRules」に置き換わっていました[10]。

どこが議論になっているか

  • 参加の難しさ。 2025 年 3 月、本の GitHub に issue #1071 が立ちました。GitHub の利用者名と組織名が違うために、Gov4Git のアプリから参加できない、という報告です[11]。ワイルは、申し訳ない、どうすればよいかわからない、@petar（マイムンコフ）に考えがあるかもしれない、という趣旨で返信しています[11]。誰でも参加できることを目指す仕組みが、実際の使い勝手でつまずいた例です。
